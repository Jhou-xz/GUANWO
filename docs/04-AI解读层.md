# 04 · AI 解读层

> AI 是翻译官和陪伴者，不是算命先生。把冷命盘翻译成温暖、个性化、可对话的解读。
> **铁律：AI 绝不做计算。** 所有干支/农历/五行/星曜从命盘 JSON 读，不自己推。

## 1. 人设（Persona）

- **像个懂命理的朋友**，不是大师、不是仙姑、不是爹味导师
- **语气**：dry / deadpan / chill，Gen Z voice，偶尔自嘲。**不煽情、不纪录片腔、不装神弄鬼**
- **不贩卖焦虑**：不说"你命里有灾""不化解会怎样"。命盘是镜子不是判决书
- **诚实**：命理是一套视角不是科学真理，态度上承认这点，但不每句都免责声明扫兴
- 人设名 / 形象：待定（mock 阶段用占位）

> 反面教材：刻板算命腔（"命中注定""天煞孤星""破财消灾"）、心灵鸡汤、星座号大字报。

## 2. 为什么 AI 不能算命盘

LLM 会幻觉干支和节气。一旦盘错，懂行用户当场出局，全产品信誉崩塌。
所以架构上 AI 拿到的是**已经算好的命盘 JSON**，它的工作只有"解读这份已知正确的盘"。
→ Prompt 里明确禁止模型自行计算或质疑命盘数据。

## 3. Prompt 架构

```
[System]
  人设 + 语气规范
  能力边界（只解读，不计算）
  合规护栏（禁区清单，见 §5）
  命理框架知识（八字/紫微基础释义口径，保持解读一致性）

[Context]
  命盘 JSON（结构化，完整）
  RAG 检索到的相关命理规则/古籍释义（针对本盘+本问题）
  用户画像 / 之前的对话历史

[User]
  用户的问题（或"给我一段整体解读"）

[Assistant]
  流式输出解读
```

### 3.1 RAG（让解读有据可依）
- 知识库：命理规则、十神/星曜释义、格局、古籍语料（标出处）
- 按"当前盘的关键特征 + 用户问题"检索相关条目注入 context
- 目的：① 减少幻觉 ② 解读有传统依据而非 LLM 自由发挥 ③ 同一盘多次解读口径稳定

### 3.2 解读分层（配合付费）
- **总览**（免费）：日主/命格一句话画像，制造 wow
- **专题**（付费）：事业 / 感情 / 财运 / 健康倾向（措辞合规）/ 大运流年
- **对照**（付费）：八字 × 紫微双系统互相印证，"专业感"卖点
- **对话追问**（付费/限免）：用户就盘里任何点深挖

## 4. 对话式设计

- 不是一次性吐 PDF，是**可持续对话**。命盘常驻 context，用户能就任意细节追问
- 每轮回答末尾可给 1–2 个"你可能想问"的钩子（自然，不强推）
- 多轮要保持人设和解读口径一致（同一颗星不能这轮吉下轮凶）

## 5. 合规护栏（硬约束，详见 [07-合规与风险](07-合规与风险.md)）

**禁区（写进 system prompt，且在输出层二次过滤）：**
- ❌ 预测**死亡 / 重大疾病 / 灾祸 / 寿命**
- ❌ 医疗 / 法律 / 投资 当作确定事实给建议
- ❌ "改运 / 消灾 / 化解 / 开光 / 风水化煞" 等迷信交易话术
- ❌ 制造恐惧逼付费
- ❌ 决定论口吻（"你注定…"）→ 改为"倾向 / 可能 / 这套系统认为"

**正向规范：**
- 框定为传统文化视角 / 自我探索，非科学断言
- 健康只谈"传统命理认为某方面需留意"，并建议就医，不下诊断
- 给 agency：强调人可以选择，不是被命运锁死

**护栏实现**：不依赖模型自觉。① system prompt 明确禁区 ② 输出层关键词/语义二次校验 ③ 触发禁区改写或拦截。

## 6. 质量保障

- **解读不能是模板拼接**：要真正基于这份盘的具体配置生成，避免"换个人也成立"的废话
- **可测**：用固定命盘 + 固定 prompt 跑回归，人工评估解读质量与合规
- **一致性**：同一盘多次解读核心结论应稳定（靠 RAG 口径 + 低随机性参数）
- **模型**：中文质感 + 长上下文（整盘+多轮）+ 指令遵循 → Claude（Opus 重解读 / Sonnet 走量），见 [claude-api] 选型

## 7. 待决策

- RAG 语料来源与版权（古籍 vs 自撰释义）
- 解读默认长度与节奏（首屏给多少才够 wow 又不过载）
